An assembly (65c816) code optimizer produced for the 816 Tiny C Compiler (816-tcc)  
Developed by Alekmaul & kobenairb and distributed under the terms of the [MIT license](https://github.com/alekmaul/pvsneslib/blob/develop/LICENSE).

816-opt is a C port of the original `816-opt.py` optimizer. It reads the `.asm` file produced by 816-tcc, runs several passes of peephole and pattern-based optimizations over it, and writes back a smaller and faster optimized `.asm` file.

## Usage
```
816opt [options] -i fileasm -o fileout
```

where file is a 65c816 file to optimize

## Options
### Files options
- `-i, --file-input <value>` asm file to optimize
- `-o, --file-output <value>` asm file optimized

### Miscellaneous options
- `-h, --help` display help
- `-q, --quiet` quiet mode
- `-v, --version` display version information

## Optimizations

816-opt repeatedly scans the assembly source, pass after pass, until no further optimization can be applied. Each pass looks for the following kind of patterns:

- **Prologue/epilogue simplification** removes the `.define <name>_locals 0` markers and collapses the matching stack-frame prologue and epilogue sequences when a function does not use any local variable.
- **Redundant store elimination** drops a store to a pseudo-register (or hardware register) when it is immediately overwritten, unused before being clobbered by a function call, or only used as a pointer right after.
- **Pseudo-register (preg) optimizations** simplify the many `store/push/load` combinations generated by the compiler for its virtual 16/32-bit registers, e.g. turning a store followed by a push into a single push, or a store followed by a load into a simple register move.
- **Increment/decrement folding** converts a store to a pseudo-register immediately followed by `inc`/`dec` operations on that pseudo-register into direct increments/decrements on the hardware register, skipping unneeded reloads.
- **Shift/rotate folding** merges a store to a pseudo-register followed by a shift on that pseudo-register (e.g. `asl`) into a single shift on the accumulator before the store.
- **32-bit value reordering** reorders the copy of 32-bit values into pseudo-registers when doing so allows further optimization of the surrounding code.
- **Comparison optimizations** (inspired by the original `optimore` tool) simplify common compare/branch sequences.
- **Branch distance optimization** shrinks long branch instructions to their short form when the jump target is close enough.
- **Dead code and local name cleanup** strips unused local variable names and other bookkeeping left over from earlier passes.

At the end of the process, the tool reports the number of optimizations performed on each pass and the total number of optimizations applied, along with the processing time (unless `-q` is used).
